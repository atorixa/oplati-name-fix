# Oplati Name Fix

Небольшой Xposed-модуль, который меняет **имя, отображаемое на экране** в приложении Oplati (`by.lwo.oplati`) — если хочется видеть в приложении другое имя, фамилию или инициалы в аватарке, отличные от тех, что привязаны к аккаунту.

Модуль переписывает текст только в момент отрисовки. Ничего никуда не отправляется, в аккаунте, профиле, базе данных и сетевых запросах ничего не меняется.

## Зачем

Oplati всегда показывает имя, записанное в аккаунте. Настройки «показывать другое» там нет, а профиль серверный — править файлы приложения бессмысленно, следующая синхронизация всё вернёт.

Модуль не трогает аккаунт: он правит только строки, которые попадают на экран. Для приложения ничего не произошло — у него по-прежнему настоящий профиль, настоящие подписи запросов и прохождение собственных проверок. Отличаются только пиксели.

## Требования

- Root с рабочей поддержкой Zygisk: KernelSU, KernelSU Next, SukiSU, APatch или Magisk.
- Ровно одна реализация Zygisk: NeoZygisk, ReZygisk, Zygisk Next или встроенная в Magisk.
- Xposed-фреймворк, умеющий грузить модули **legacy API 93**: Vector или LSPosed.
- Установленное приложение Oplati.

Проверенный стек (работает целиком):

| Компонент | Версия |
|---|---|
| Устройство | Google Pixel 8 (`shiba`) |
| Прошивка | Android 17 QPR2, `CP4A.261105.040.A1` / 16581829 |
| Root | KernelSU 3.3.1 (`me.weishu.kernelsu`) |
| Zygisk | NeoZygisk 2.4 (289) |
| Xposed | Vector 2.2 (3080) |
| Oplati | 1.46.1 (210010469) |

Более новые сочетания должны работать, если живы все три слоя выше. Если на устройстве вообще не работают Xposed-модули, этот тоже не заработает — сначала чинится фреймворк.

## Установка

1. Скачай `OplatiNameFix.apk` из Releases.
2. Установи как обычное приложение:

   ```sh
   adb install -r OplatiNameFix.apk
   ```

   либо просто открой файл на телефоне.
3. Открой Vector (или LSPosed) → **Модули** → включи **Oplati Name Fix**.
4. В списке scope отметь **Oplati** (`by.lwo.oplati`). Само приложение модуля всегда в своём scope, там ничего делать не надо.
5. Перезагрузись — или как минимум сделай force-stop Oplati, чтобы приложение стартовало уже с загруженным модулем.
6. Запусти Oplati. Имя уже должно быть заменено на нейтральное дефолтное.

Модуль ставится с заглушками по умолчанию — `Имя` / `Фамилия` / `ИФ` — так что свежая установка сразу видно, что работает, а не молчит. Сразу после установки их надо поменять.

## Настройки

Экран настроек открывается из иконки в лаунчере, из страницы модуля в Vector (кнопка с шестерёнкой) или из шелла:

```sh
adb shell am start -n love.atorixa.oplatinamefix/.SettingsActivity
```

| Поле | Смысл |
|---|---|
| **Name the app shows now** | Имя, которое приложение показывает сейчас. Регистр не важен. |
| **Name to display** | Что показывать вместо него. |
| **Surname the app shows now** | Текущая фамилия в приложении. |
| **Surname to display** | Что показывать вместо неё. |
| **Avatar initials now** | 1–2 символа в кружке профиля, например `AS`. |
| **Initials to display** | Что должно быть в кружке, например `AB`. |
| **Extra replacements** | Необязательно, по одной паре `старое=новое` на строку — для любых других строк. |

Кнопки:

- **Save** — сохраняет конфиг и показывает тост.
- **Reset** — возвращает нейтральные дефолты.
- **Open Oplati** — открывает целевое приложение для проверки результата.

Если «текущие» поля пустые, соответствующая замена пропускается. Поле инициалов независимое: если его оставить пустым, модуль соберёт инициалы сам из первых букв заданного имени и фамилии.

После сохранения Oplati нужно переоткрыть — уже нарисованные экраны держат старый текст, пока не будут созданы заново.

## Как это работает

Модуль загружается только в процесс `by.lwo.oplati`. Внутри него он:

1. **Хукает `TextView.setText(CharSequence)`** у всех классов `TextView`, которые трогает приложение. Это покрывает классические вьюхи, нижние шторки и список профиля.
2. **Лениво хукает Compose**: когда в classloader приложения виден `androidx.compose.ui.text.AnnotatedString`, хукаются и его конструкторы — текст, собранный Compose, тоже переписывается. Хук ставится при первом обращении и молча пропускается на сборках без Compose.
3. **Переписывает совпадения за один проход.** Все пары замен компилируются в одну альтернацию и применяются через `Matcher.appendReplacement`, поэтому результат замены никогда не будет повторно пойман следующей парой — каскадов вида `A → B → BB` не бывает.
4. **Уважает границы слов.** Каждая альтернатива обёрнута в `(?<![\p{L}\p{N}])` и `(?![\p{L}\p{N}])`, поэтому короткое старое значение не может совпасть с хвостом другого слова.
5. **Сохраняет регистр.** `ВСЁ КАПСОМ`, `С Заглавной` и `строчные` дают соответствующую форму замены.
6. **Читает конфиг один раз на экран, а не на каждую строку.** Значения приходят из хранилища модуля через read-only `ContentProvider`, который отвечает только самому модулю и целевому приложению.

Чего модуль осознанно не делает:

- не хукает сеть, криптографию, keystore, базу данных и файловые API;
- не меняет APK, его подпись и ресурсы;
- не трогает аккаунт, профиль и тела запросов;
- не собирает, не логирует и не передаёт увиденные строки (в лог попадают только счётчики замен под отдельным тегом, и только в debug-сборке).

## Ограничения

- **Только то, что рисуется.** Если Oplati строит из имени картинку, PDF или payload QR-кода, этот контент не меняется. Текущая версия — текстовая.
- **Только два текстовых пути выше.** Если будущая версия Oplati начнёт рисовать имя через `Canvas.drawText`, WebView или нативную вьюху, модуль это не покроет, пока для них не добавят хук.
- **Только приложение в scope.** Всё, что вне `by.lwo.oplati`, не затрагивается.
- **Это не инструмент приватности.** Сервер, аккаунт и хранилище устройства по-прежнему содержат настоящее имя. Модуль меняет отображение, а не личность.

## Сборка

Проект собирается обычным JDK и command-line tools Android SDK. Без Gradle и без Android Studio.

```powershell
pwsh -NoProfile -File build.ps1 -Sdk "C:\path\to\android-sdk"
```

Результат: `build\OplatiNameFix.apk`.

Нужные пакеты SDK:

```sh
sdkmanager "platforms;android-36" "build-tools;36.0.0" "platform-tools"
```

Скрипт выполняет `javac` → `d8` → `aapt2 link` → вкладывает `classes.dex` и `assets/xposed_init` в APK → `zipalign` → `apksigner`. Keystore берётся из `keystore.jks`; перед сборкой создай свой:

```sh
keytool -genkeypair -keystore keystore.jks -alias test -keyalg RSA -keysize 2048 -validity 10000
```

Важно: `keystore.jks` намеренно в `.gitignore`. Никогда не публикуй ключ, которым подписываешь релизы.

## Если что-то не работает

**Совсем ничего не меняется.**

1. Убедись, что модуль включён в Vector и Oplati есть в его scope.
2. Проверь, что жив фреймворк: `logcat | grep -i vector` должен показать загрузку модуля в процесс приложения.
3. Проверь, что конфиг сохранился:

   ```sh
   adb shell su -c 'cat /data/data/love.atorixa.oplatinamefix/files/config.properties'
   ```

4. Сделай force-stop и открой Oplati заново.

**Шапка меняется, а экран профиля нет (или наоборот).**

Экран уже отрисован. Переоткрой приложение: каждый экран читает конфиг в момент создания.

**В кружке остались старые буквы.**

Заполни **Avatar initials now** явно. Многие приложения считают инициалы из поля, которого модуль не видит, поэтому автоматическую пару вывести нельзя.

**Приложение падает после включения.**

Выключи модуль, сделай force-stop приложения и приложи лог:

```sh
adb logcat -d | grep -i -E 'OplatiNameFix|AndroidRuntime'
```

**Логи для отладки.**

```sh
adb logcat -s OplatiNameFix
```

## Приватность

- APK не просит разрешений и не содержит сетевого кода.
- Конфиг лежит в приватном хранилище модуля: кроме самого модуля и целевого приложения его никто не прочитает.
- Ничего не выгружается, не дублируется и не пишется в логи вместе со значениями. В логи попадают только счётчики и имена пакетов.
- Удаление модуля убирает APK и его данные; само приложение Oplati остаётся нетронутым.
